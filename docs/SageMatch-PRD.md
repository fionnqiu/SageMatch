## 1. 产品概述

### 1.1 背景

求职者在技术面试准备中面对三个具体问题：

1. **通用题库与自身岗位不匹配**。市面题库按知识点组织，而真实面试考察的是"这个岗位需要什么"。用户需要自己判断"哪些题跟我有关"，这个判断本身就有成本。
2. **缺少真实面试的压迫感**。知道答案不等于讲得清楚——后者只能通过多轮对话练习，且必须有人追问。
3. **面试表现没有数据沉淀**。哪类问题薄弱、比上次有没有进步，全靠感觉。

> **v1.5 说明**：第 2、3 条的表述已随「删除答题板块」调整——本产品的训练闭环落在**模拟面试 + 复盘**上，而不是刷题。第 1 条的痛点仍由「岗位 → 岗位要求分析与针对性出题」解决。

### 1.2 产品定位

**面向求职者的岗位定制化面试训练系统** —— 以目标岗位的描述为起点分析岗位要求并生成针对性题目，通过多轮模拟面试训练表达能力，并以数据复盘形成训练闭环。

> **与项目名的解耦（v1.6 明确）**：本定位与「知弈」/「SageMatch」这个**代号**无关。产品是「**面试训练系统**」，不是"对弈"或"博弈"类产品——项目名不承载产品语义，界面与文档一律不使用「对弈」「博弈」等措辞（见文首「命名约束」）。

### 1.3 核心价值主张

| 方面 | 主张 |
|---|---|
| 对岗 | 训练内容来源于目标岗位的真实要求，而非通用题库 |
| 可练表达 | 提供接近真实面试的多轮对话训练（面试官会追问、会说话），而非单向答题 |
| 有据可依 | 每场模拟面试的表现、薄弱点、改善趋势均可追溯 |

### 1.4 产品边界（明确不做）

- 不做招聘方侧功能（简历筛选、候选人管理、面试官工具）
- 不提供内推、岗位投递、薪资查询等求职服务
- 不存储或分发第三方题库内容

## 2. 目标用户与使用场景

### 2.1 用户角色

**角色 A · 求职者（主要用户）**

- 特征：正在准备技术面试，有明确的目标岗位
- 核心诉求：在有限时间内把训练集中在"这个岗位真正会问的内容"上；需要练表达而不只是背答案
- 使用环境：以碎片时间为主（工作日晚间、通勤后），且常处于不方便出声的场合（地铁、合租房间），这一环境特征直接影响交互设计

**角色 B · 系统管理员（次要用户）**

- 特征：系统运维者 / 内容维护者
- 核心诉求：能管理模型来源、维护知识物料、验证检索效果与出题质量
- **进入方式（v1.8 明确）**：首版以**管理员口令**进入管理端（可选叠加 IP 白名单）；**用户端匿名可用**。首版**不建用户表、不做登录注册**，本文档**不新增认证类 FR**。对外提供服务前须升级为真实鉴权（已登记为上线前置依赖，见技术 §8「上线前置事项」）

### 2.2 用户故事

| 编号 | 角色 | 场景 |
|---|---|---|
| US-01 | 求职者 | 我拿到一份心仪的岗位描述，想快速知道"这个岗位会考哪些方面" |
| US-02 | 求职者 | 我想用接近真实面试的方式练一遍——面试官会追问、会打断，而不是给一道题让我慢慢想 |
| US-03 | 求职者 | 练完我想知道刚才哪些地方答得不好，以及下次具体该怎么改 |
| US-04 | 求职者 | 我想看到自己的进步趋势，而不是每次都从零开始 |
| US-05 | 求职者 | 我在不方便出声的地方，只想打字回答；但我想听到面试官提问，感受一下真实压力 |
| US-06 | 管理员 | 我要更换模型供应商、或调整知识库的检索行为，并且能立刻验证改动是否有效 |

> **v1.5 说明**：US-01 原先为"…并针对性**练一批题**"，其中"练题"随答题板块删除，收敛为"知道会考哪些方面"。**US-02 / US-03 中的"练"指模拟面试本身**，不涉及作答板块，故保留原表述。

### 2.3 核心用户旅程

```
拿到岗位描述
  → 在会话界面提交给系统 → 系统分析岗位要求并检索知识库（自动完成，无需确认）
  → 系统生成针对性题目（含覆盖度、不重复、干扰项质量校验）
  → 发起模拟面试（多轮对话 + 追问；面试官文字+语音发言，题目随提问逐题出现）
  → 获得复盘报告（评分 / 失分点 / 改进建议）
  → 针对薄弱环节重开一场模拟面试
```

> **关于「生成题目」的定位（v1.7 更新）**：题目是**出题链路的交付物**，也是管理端出题质量评测的验证对象。本期**不提供面向用户的作答交互与答题记录**（原 FR-U-10 ~ U-13 已删除），**也不提供题目集浏览页面**——题目在用户端**只随面试提问逐题出现在模拟面试界面**。

> **主流程所在的界面（v1.7 明确）**：用户端**只有两个界面**——① **会话界面**（提交岗位、看实时出题进度、发起模拟面试）；② **模拟面试界面**（题目随提问出现、多轮问答、复盘报告）。**所有主流程都落在这两个界面内，不存在第三个功能页面。**

> **FR-U-11 的设计意图（v1.7 新增）**：题目**不是列表式呈现**给用户翻阅，而是**跟着面试官的提问节奏逐题浮现**。这样做的三个理由：① 与真实面试一致（面试时看不到题单）；② 用户不会被"还有 N 题没问"干扰作答状态（与 FR-U-19 不显示实时评分的意图同源）；③ 用户端因此不需要独立的题目集页面，界面数量收敛为两个。

> **★ 取题机制：题集驱动 + 题内自由追问（v1.8 新增，H1）**
>
> FR-U-11 要求"面试官问到某题时该题以卡片浮现"，而面试官是**自主 Agent**（走 ReAct，会依用户回答动态追问）——因此"**面试官问什么**"与"**题目集里有什么**"必须显式对齐。**本期口径**：
>
> | 方面 | 口径 |
> |---|---|
> | **取题主线** | **题集驱动** —— 面试官从题目集**按顺序取题**，保证**每道被问到的题都有卡片可渲染**，且与 **FR-U-04 的覆盖率 ≥90% 天然自洽** |
> | **题内追问** | **不受限** —— 在**同一道题内**，面试官可依用户回答**自由多轮追问**（FR-U-10 的能力完全保留） |
> | **取下一题的实现** | 由**编排层按覆盖进度直接算好并注入上下文**，**不是工具调用** —— 因此不增加在线 LLM 往返、不破坏在线预算，工具白名单也不变 |
>
> **为什么不做"面试官驱动"（面试官自由决定问什么，问到的题才去取卡片）**：它更"自然"，但会**问到题目集里没有的题**（此时无卡片可展示，需额外定义降级行为），且会让 **FR-U-04 的覆盖率失去约束力**。两个代价都高于收益。
>
> 具体实现见 Agent 文档 §7.1 形态二（`InterviewerAgent` 取题策略）与 §4.2 约束 A（"下一题"走高频只读状态上下文注入）。

## 5. 数据实体（业务视角）

| 实体 | 说明 | 关键关系 |
|---|---|---|
| 用户 | 系统使用者（求职者 / 系统管理员） | 1 用户 → N 岗位、N 模拟面试 |
| 岗位 | 用户提交的目标岗位（含原始描述与岗位分析结果） | 1 岗位 → N 题目集 |
| ~~考察维度~~（**v1.9：内部实现细节，产品层不出现**） | 系统内部用于检索与出题分片的中间结构，**不在用户端展示** | N ↔ N 题目 |
| 知识物料 | 管理员上传的技术资料 | 1 物料 → N 内容片段 |

| 复盘报告 | **整体评分**、失分点、改进建议（**v1.9：无分项得分**） | 1 面试 → 1 报告 |
| 能力画像 | 跨场次的**强弱与变化**记录（**v1.7：记忆层内部机制，用户端不暴露**） | 1 用户 → 1 画像 |
| 评测任务 | 管理员发起的质量评测 | 关联配置版本 |
| 模型与语音供应商配置 | LLM / Embedding / ASR / TTS 供应商的连接信息、可用模型清单与能力声明 | 被调用日志与报告引用 |
| 参数配置 | 检索与生成参数。**本期不进管理端**；后续由后端 config 文件承载，被题目集与评测任务引用 | 后置实现 |
| 调用日志 | 每次模型 / 语音调用的供应商、模型、prompt 与 rubric 版本、耗时、结果状态 | 全部质量指标的归因基础 |
| 审计日志 | 管理端配置变更与物料变更的操作记录 | 关联操作者（NFR-08） |

> **v1.5 变更**：删除「练习记录」实体（原为"题目集合 + 用户作答行为"），改为「**题目集**」（只剩出题产物与参数快照，不含作答行为）。**题目实体保留**——它是 FR-U-03 / U-06 的承载者，也是 §6.1 四项指标的验证对象。
>
> **v1.7 变更**：① 新增「**能力画像**」实体并注明**用户端不暴露**（原为 FR-U-25 成长趋势视图的载体，该需求已删除，画像降为记忆层内部机制供 `CoachAgent` 引用历史）；② 「考察维度」的关键关系中去掉"用户确认"语义（维度自动生效）；③ 「题目」的展示出口收敛为**模拟面试界面内的题目卡片**（全系统无题目集页面）。

## 6. 度量指标与验收标准

### 6.1 出题质量

| 指标 | 定义 | 验收目标 |
|---|---|---|
| **出题覆盖度**（v1.9 改名） | 题目集覆盖的考察要点数 / 系统内部识别出的考察要点总数（**内部指标，界面不展示**） | ≥ 90% |
| 题目重复率 | 语义重复题目数 / 题目总数 | < 10% |
| 干扰项有效性 | 在不提供知识内容的盲测条件下，模型的误选比例 | 20%–50%（过低说明无迷惑性，过高说明答案不明确） |
| 出题可用率 | 人工抽检认定为"可直接使用"的题目比例 | ≥ 80% |

> **口径说明（与 FR-U-04 / FR-U-05 的关系）** ★ 2026-09-21 确认（**v1.8 修正编号**：原写"FR-U-05 / FR-U-06"，属二次前移前的旧编号）
>
> 两项 FR 与本节指标**使用同一组数值，不存在"目标值 / 验收线"两套标准**：**出题覆盖度 ≥ 90%**、重复率 **< 10%**。
> - **出题覆盖度**：系统仍须执行一轮补生成（流程要求），但**验收线是 90% 而非 100%** —— 补生成后仍存在少量未覆盖项**不判失败**。统计时点为「补生成 1 轮之后」。
> - **重复率**：统计范围为「同一内部出题分片内的题干对」。跨分片的题干重复**单列观察**，不计入本指标，但实现上应尽量避免。
> - 干扰项有效性与出题可用率同理，直接以本节数值为验收线。

> **★ 测量渠道（v1.5 明确，v1.7 复核仍成立）**：本节四项指标的测量对象是**题目集本身**，与用户是否作答无关、也与用户能否浏览题目无关。因此**作答板块删除（v1.5）与题目集页面删除（v1.7）后，本节的验收方式与数值均不变**，计算渠道为：
>
> | 指标 | 计算渠道 |
> |---|---|
> | 出题覆盖度 / 重复率 | 业务出题链路内置(`check_coverage` / `check_duplicate`)+ **管理端出题质量评测(FR-A-13)复核** |
> | 干扰项有效性 / 出题可用率 | **仅管理端出题质量评测（FR-A-13）**（抽样盲测 + 人工抽检） |
>
> **必须保留出题能力的原因正在于此**：删除作答交互不影响用户旅程的完整性，但**删除出题则会同时抽掉本节四项指标的测量对象与管理端评测链路（FR-A-13）的业务参照**——那时"评测合格"将无法推出"业务合格"。
>
> ★ **v1.7 抗辩说明（重要）**：本轮再次收缩范围（删维度确认、删题目集页面）**可能被误读为"可以顺带把出题也删了"**。恰恰相反——**出题链路的存在理由在两次收缩后变得更强了**：
> - 用户端已经**没有任何地方能看到题目**（只在面试中逐题浮现），题目对用户的"可见性"降到了最低；
> - 但 §6.1 的四项指标**仍然需要一个业务出题链路来产生被测对象**，否则验收无标的；
> - 因此**出题是"看不见但必须在"的一层**——它的消费者从"用户看题"变成了纯功能性的两个：**模拟面试提问** + **管理端评测**。
>
> **一句话**：范围两轮收缩动的都是「用户端界面」，**从未动过「出题能力」本身**。

### 6.2 评分质量

| 指标 | 定义 | 验收目标 |
|---|---|---|
| 评分一致性 | 同一场面试的回答集重复评分 **N=5** 次，**整体分**（10 分制）的标准差 | ≤ 0.5 分 |
| 排序稳定性 | 同一批回答（同一次评测的固定样本集）在多次评分下，回答之间评分相对排序保持一致的比例 | ≥ 90% |

> **口径说明**：两项指标均以评分员（`ScorerAgent`）产出的**整体分**为测量对象（见技术方案 §4.6）。**v1.9 连带调整**：因 FR-U-20 已取消分项得分，一致性不再以“维度分”为测量对象，只算整体分。复盘文案（温度 0.3，可读性导向）**不参与**一致性计算，否则会把文案的随机性误算进评分稳定性。排序稳定性的样本量由评测任务参数指定。

### 6.3 模拟面试质量

| 指标 | 定义 | 验收目标 |
|---|---|---|
| 历史引用准确率 | 面试官引用历史回答时与事实相符的比例（含语音作答内容） | ≥ 95% |
| 长会话稳定性 | 60 分钟会话中上下文相关错误（重复提问、忘记前文）出现次数 | ≤ 1 次 / 场 |
| 语音转写可用率 | 语音作答被正确转写且语义未失真的比例 | ≥ 95% |
| 复盘可用率 | 人工判定"问题具体、建议可执行"的复盘比例 | ≥ 80% |

### 6.4 系统指标

| 指标 | 验收目标 |
|---|---|
| 物料入库成功率 | ≥ 95%（正常格式文档） |

> **v1.5 删除项**：原「出题端到端耗时 ≤ 2 分钟」一行已移除——它与 NFR-01 完全重复（NFR-01 的表述更完整，含"仅计系统处理时长"的口径说明），保留两处只会带来维护漂移。**该指标以 NFR-01 为准**。
>
> **v1.8 删除项（N3）**：原「语音播报启动延迟 ≤ 1 秒」与「语音作答后的响应间隔 ≤ 1.5 秒」两行一并移除——**理由与上一行完全相同**（它们与 NFR-02 完全重复）。**全系统性能指标一律以 §4.1 的 NFR 为准**，本节不再重复承载，避免双源漂移。

## 7. 范围界定

### 7.1 本期范围（首版 = 全部主线功能）

> **★ 用户端只有两个界面（v1.7 明确）**：下表的前三行是**功能分组**，**不是三个页面**——它们全部实现在**两个界面**内：**会话界面**（承载岗位提交、出题进度、发起面试）与**模拟面试界面**（承载题目逐题浮现、多轮问答、复盘报告）。**本期不产出任何第三个用户端功能页面。**

**用户端**

| 功能分组 | 覆盖内容 | 落在哪个界面 |

| 模拟面试 | 多轮追问、面试官文字+语音双形态发言、用户文字或语音作答且可切换、长会话、历史引用、**题目随提问逐题浮现** | **模拟面试界面** |

**管理端**

| 板块 | 覆盖内容 |
|---|---|
| 模型供应商配置 | 两类协议接入、连接配置、连通性测试、切换后上层无感 |

>
>    ★ **v1.6/v1.7 补充（用途唯一性）**：出题能力的**唯一消费方是模拟面试与管理端评测**，**不存在"面向用户答题"这个消费方**。经过 v1.7 的第二次收缩，**题目在用户端已没有任何"列表式"展示出口**——只在面试中随提问逐题浮现。**这不削弱出题链路的价值，反而说明它已完全变成"看不见但必须存在"的支撑层**（详见 §6.1 的抗辩说明）。
> 2. **「题目集浏览页面」*≠*「题目集存在」** ★ v1.7 新增。**删除的是"看题列表的页面"，不是"题目集这个产物"**。`question_sets` 表与 `questions` 表**完整保留**（技术文档 §4.7）——它们仍是：① 面试官提问的取数来源；② §6.1 四项指标的测量对象；③ 管理端 FR-A-13 评测的被测对象。**一句话：题目集是数据产物，页面只是它的一个（已取消的）呈现方式。**
> 3. **「岗位要求审核环节」≠「岗位分析」** ★ v1.7 新增，v1.9 去词。**删除的是“用户审核”这一步交互，不是“分析”这个能力**。岗位分析与知识检索完整保留且**照常出题**——只是分析结果**自动生效且不在界面上展示**（v1.9），用户不再看到任何编辑表单或维度卡片。
> 4. **「多套参数组合管理」** 指用户可创建、命名、切换多套参数组合。本期检索与生成参数只有**一套生效值**；技术方案中的 `retrieval_profile`（`offline` / `online`）是**代码内置的固定档位**，不是用户可管理的参数组合。**v1.10**：top-k / top-p / temperature / 分块大小 / 分块重叠**不进管理端**，后续由后端 config 文件承载。
> 5. **「评测结果版本对比」** 指对两次评测任务的结果做自动并排对比视图。FR-A-07（v1.10）是**单次召回看命中片段**，不做 A/B 改参对比；与评测任务的版本对比是两件事。
> 6. **「面试暂停与跨会话恢复」** 指用户主动暂停面试后改日续做。**单次会话内的断线重连与状态恢复**属 NFR-03 长会话稳定性的组成部分，不在排除之列。
> 7. **「错题本与收藏」** 指面向用户组织错题的功能。出题链路内部的**避让池**仅用于同一岗位题目集内的去重，不跨题目集、不对用户暴露，不属于错题本。

## 8. 风险与依赖

| 风险 | 影响 | 应对方向 |
|---|---|---|
| 知识物料来源不清 | 合规风险，影响公开运营 | 物料以技术文档与自有资料为主，逐份记录来源，不引入第三方题库 |
| 出题质量不稳定（干扰项弱、题目重复） | 出题质量无法验证，进而影响面试提问的针对性 | 按 6.1 建立质量指标并纳入常规评测；引入盲测质检环节。**注意：作答板块删除（v1.5）后用户侧观感反馈通道消失，题目集页面删除（v1.7）后连"看到题目"这个渠道也没了——质量验证完全依赖管理端评测（FR-A-13），这是唯一出口** |
| 长会话中上下文丢失 | 模拟面试体验崩坏（最致命的体验问题） | 将"历史引用准确率"设为硬性验收指标，专项验证 |
| 语音转写错误影响追问 | 面试官基于错误内容追问，体验严重受损 | 将"语音转写可用率"设为验收指标；对专有技术名词做识别校验 |
| 评分不可复现 | 复盘与趋势数据失去可信度 | 将"评分一致性"设为硬性验收指标 |
| 语音能力（播报与转写）依赖外部服务 | 延迟与成本不可控 | 设置降级路径（NFR-12）；管理端支持多供应商切换 |
| 范围膨胀 | 主线功能未完成即陷入细节 | 按 7.2 严格执行排除清单 |

## 9. 交付顺序建议

各板块存在依赖关系，建议按以下顺序推进（非产品分期，仅为实现顺序）：

1. **管理端基础**：模型供应商配置、物料上传与处理 —— 用户端出题依赖知识库
2. **知识库配置与召回测试** —— 出题质量依赖检索效果
3. **会话界面 + 出题链路**：岗位提交 → 岗位分析（自动完成）→ 生成题目（含出题覆盖度、不重复、干扰项要求）→ 出题进度反馈
4. **模拟面试（文字）**：多轮追问、历史引用、**题目随提问逐题浮现**
5. **模拟面试（语音）**：播报、语音作答转写、播放控制、降级路径
