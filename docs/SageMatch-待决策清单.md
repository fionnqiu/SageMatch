## ★ 本轮范围决策（第三次）：维度降为内部机制（2026-09-21）

**用户指示**："删除所有文档和设计稿的"维度"概念，我们逻辑上不处理"维度"。" → **追问确认**："维度的识别是为了进行题目的检索，但是在前端页面不进行展示和交互。"

**执行口径：降为内部机制——识别保留，产品层与界面全部去词。**

| 处理 | 内容 |
|---|---|
| **保留** | 维度识别照常执行（作用是为**题目检索**提供抓手）；出题链路**仍以它作并行分片键**（12 维度 / 并发 ≥8 的延迟预算不变）；`dimensions` / `dimension_id` / `covered_dimensions` / `check_coverage` / `ProfileAnalystAgent` **均保留** |
| **移除（界面）** | 会话舱的「考察维度识别结果」卡片**整张删除**（用户选择"直接删卡片，不留替代"）；模拟面试题卡的「所属维度」标签删除；复盘屏的「各维度得分细则」删除 |
| **去词（产品层）** | PRD 用户端章节全量去词：FR-U-01 / U-02 / U-03 / U-05 / U-09 / U-11、§1.2 定位、§2.3 旅程、§3.1.2 界面定位、§7.1 范围表、§7.2 排除清单与边界界定、§9 交付顺序 |
| **改名** | 6.1 指标「考察维度覆盖率」→ **「出题覆盖度」**（数值仍 ≥90%，达成机制不变） |
| **改写** | **FR-U-18 面试收尾改阈值驱动**——原"核心考察维度覆盖完毕后收尾"改为"轮次或时长达到内部安全阈值、或判断考察已充分时收尾"；`covered_dimensions` 降为**辅助参考**。**FR-U-20 复盘取消分项得分**——只给整体分 + 失分点 + 改进建议 |
| **补声明** | 三份文档头部各新增一条**内部实现口径**：维度仅作内部检索与出题分片的实现细节，**不是产品概念**，用户端不展示不交互 |

**为什么收尾不能再看覆盖度**：v1.9 起维度对用户完全不可见，若仍以"覆盖完毕"作为唯一收尾条件，收尾时机会被一个**用户看不见的内部状态**支配；而 FR-U-16 本就不设轮次上限，两者叠加会让面试时长**不可预期**。改阈值驱动后，收尾**可预测、可验收**。

**连带影响**：① **6.2 一致性测量对象收窄**——由"维度分与整体分"改为**整体分**（因分项得分取消）；② **对外只呈现整体分**，维度分与加权合成仍为内部实现；③ `design.pen` 已同步清理**13 处**维度落点（含管理端 4 处：覆盖率标签、重复率标签、物料表列名、召回测试输入提示）。

**首版验收标准未降低**：6.1 / 6.2 / 6.3 三组指标的**数值一字未动**——本轮的"去词"只动**呈现层**，不动**测量口径与数值**。

> - **从另一台机器用内网 IP 访问 → `getUserMedia` 仍被拒**，语音功能不可用 ❌（需 Chrome 启动参数 `--unsafely-treat-insecure-origin-as-secure=http://<内网IP>:8000`，或自签证书）
